## Implemented on V2 branch

- Added a real /tournaments directory page with known competition destinations and an optional current-season indicator from the PostgreSQL directory reader.
- Added a bounded listPostgresLeagueMatches reader using only columns in base migration 0001, with a hard 1,000-row maximum.
- Added GET /api/competitions/matches?league=..., validating an allowlist of supported competition names and returning an explicit public match projection. It selects the base PostgreSQL reader when FACTSPORT_MATCHES_BACKEND=postgres; legacy Supabase fallback remains until the migration/cutover gates pass.
- Added the competition standings branch to GET /api/cache/standings, with league-code allowlisting and explicit projection; PostgreSQL standings are enabled only by FACTSPORT_COMPETITIONS_BACKEND=postgres.
- Removed direct browser Supabase access from LiveStandings. It now obtains matches and standings from same-origin APIs and refreshes every 15 seconds. The existing live status/stage presentation is retained.
- Removed bookmaker affiliate banner/promo components from public news, article, highlights, standings, match, tournament, leaderboard and live route surfaces. No AdSense code was introduced; policy review and approved monetization placement remain a separate gate.
- Added/extended tests for tournament directory/detail, bounded public projections, same-origin live standings reads, public promo absence, and CI path triggers.
