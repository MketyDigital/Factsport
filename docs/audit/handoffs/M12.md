## Changes on this branch

- Added GET /api/match/[id]/playback. It validates the match UUID, reads the legacy match's status/date and media fields, and withholds media URL fields until the server-side 15-minute pre-kickoff unlock. After unlock it returns the existing video or audio source and preserves the secondary audio URL when video is selected. The existing streamio sentinel remains supported.
- Added GET /api/match/[id]/analysis. It checks the server session, then the legacy profiles.is_vip value. Unauthenticated/non-VIP responses disclose only whether analysis exists; the analysis object is returned only to a verified VIP profile.
- Added SecureMatchPlayer, which fetches playback state from the same-origin API instead of receiving raw media URLs as page props.
- Updated ProBettingSlipLock to fetch authorized analysis from the server API; removed browser Supabase access and stopped passing pro_analysis through MatchMobileHub.
- Changed /match/[id] to use an explicit legacy match column projection and pass a restricted public DTO to MatchHeaderClient and MatchMobileHub. Raw stream/audio/video URLs, pro_analysis, campaign IDs and affiliate URLs are excluded from that DTO.
- Narrowed the site_settings query to the three announcement fields used by the match page.
- Added tests/match-media-access.test.cjs for DTO exposure, locked playback responses, authorized media/audio handling and server-side VIP checks.

## Remaining gaps — do not mark match centre complete

1. Both new APIs still query legacy Supabase; they are not yet backed by PostgreSQL.
2. Playback returns the provider URL after the time gate. It does not yet implement the signed short-lived playback grant or controlled proxy required by the M11 design. Provider capabilities and the existing StreamIO/video flows must be preserved while implementing that boundary.
3. VIP authorization still uses legacy profiles.is_vip, not the V2 entitlement/role service. Payment/entitlement migration and revocation semantics remain open.
4. No browser E2E covers before/after kickoff, live/finished, audio-only, video+audio, streamio, missing media, expired/invalid links, non-VIP, VIP, expired entitlement or upstream failure.
5. Canonical/legacy match alias population, prediction/campaign foreign-key parity, match events/stats/lineups/H2H, live three-second feed, ticker, announcements, chat, MOTM and prediction journeys still need full parity and service migration.
6. Keep FACTSPORT_MATCH_DETAIL_BACKEND disabled until migration 0008 is applied in isolated staging, aliases are reconciled, and the complete match detail contract is verified.
